## Highlights

- **Runner (new):** a model can now work like a coding agent inside a container on *your* computer. The runner (`multigpt-runner`, a static Rust program for Linux amd64 and arm64, downloaded from MultiGPT) connects outbound to the server and starts rootless Podman containers from a fixed, checked template: read-only root, no capabilities, resource limits, no network by default. Tools: `read`, `write`, `edit`, `glob`, `grep`, `bash`, `serve`, `publish`, `apt_install`, `telnet` and `setup_host`. The work is kept as a **git bundle on the server** (every change is a commit), with a live terminal and a sandboxed preview in the browser. See the wiki page "Runner".
- **Web server and ports:** lighttpd (static files only) inside the container, exported on the computer as ports 24080 (http) and 24443 (https, self-signed). By default the ports are bound to `0.0.0.0`, i.e. **visible to the whole home network without a login**; `MGPT_EXPOSE_BIND=127.0.0.1` restricts them to the computer itself.
- **Package sources:** an optional mode lets the model install Debian packages (`apt_install`), pip, npm, GitHub and cargo packages through a proxy that only reaches an allow-list of hosts (never the home network).
- **Trust model:** server commands are signed with a per-installation key, the service catalogue and the runner binaries with a per-release key; role permission "Runner" and API key scope `runner.use` (team agents can use a runner through MultiGPT, never directly); a monthly "Runner time" budget; every access goes through MultiGPT.
- **LM Studio as an interface of its own:** one server address, chat over `/v1`, model management over `/api/v1`. Tokens per second and time to first token are shown for every answer; a full GPU now asks whether pinned models may be swapped out; reasoning levels come from LM Studio with a default per model; memory estimates for Gemma 4 and Qwen3.8; chat models load with `parallel 1` unless configured otherwise.
- **Server-side scratchpad:** files produced by tool calls (also SVG, sanitised) are kept and shown with the answer; MCP servers can be reconnected from the chat.

## Upgrade notes

- The package now depends on `git` and ships the runner binaries and the signed catalogue under `/usr/share/multi-gpt/runner`; a new service `multi-gpt-runner` and an nginx location `/runner/ws` (and `/runner/pty/`) are installed. The installation key is created on first install (`mgpt-ctl runner pubkey`); `mgpt-ctl runner keygen --force` disconnects all runners.
- Roles with the right "Use runner" (admins and adults by default) can pair a computer on the page "Runner". The runner needs Podman and a systemd user session; the work image is pulled from `ghcr.io/beerlesklopfer/multigpt-runner-work` (set to public once).
- Building the runner yourself needs Rust 1.88 or newer; the downloadable binaries do not.
